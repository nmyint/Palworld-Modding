## Delivered scope

Added the public command:

```powershell
Get-PwWorkshopDashboard
```

The command returns one structured, deterministic, read-only snapshot with the
following fixed section order:

1. Workshop
2. Repository
3. Profile
4. Catalog
5. Deployment
6. UpdateCache
7. Diagnostics

The model composes existing commands instead of duplicating their business logic.
It remains independent of terminal formatting and serializes to JSON.

## Section boundaries

### Workshop

Uses `Get-PwWorkshopInfo` for the established module/runtime/session summary.

### Repository

Uses local read-only Git commands to report:

- branch and commit;
- upstream;
- ahead/behind counts from locally known refs;
- clean/changed state;
- staged, unstaged, untracked, and conflict counts.

It does not fetch, pull, switch branches, stage, commit, push, or change refs.

### Profile

Uses the active configuration, profile validation, and mod-set preview commands.
It preserves `IsValid` and `IsReady` as separate states and returns deterministic
selected-mod records.

### Catalog

Uses the persistent catalog and reports compact deterministic records, Nexus-ID
coverage, installed-version coverage, archive presence, source counts, and
reconciliation counts. Nexus identity remains provenance rather than byte
integrity evidence.

### Deployment

Uses the existing deployment configuration, assembly plan, assembly validation,
and deployment-readiness providers. Nested provider errors are retained without
discarding other deployment information.

### UpdateCache

Uses `Get-PwNexusMetadataCacheInfo` only. The dashboard never refreshes or
replaces the cache. A section may be collected successfully while the cache
correctly reports `IsComplete = false` or `IsCurrent = false`.

### Diagnostics

Returns the existing `Get-PwDiagnostics` result. Dashboard collection
completeness remains separate from diagnostic health.

## Failure isolation

Each top-level provider is collected independently. If one provider fails:

- that data property is `null`;
- the corresponding `Sections` row is `Unavailable`;
- the provider message is retained;
- all successful sections remain available.

This prevents one local tool or provider limitation from being misreported as a
failure of the complete workshop.

## Read-only safety boundary

Focused tests verify that dashboard collection does not invoke:

- `Update-PwNexusMetadataCache`;
- `Update-PwModCatalog`;
- `Build-PwProfileDeployment`;
- `Invoke-PwDeployment`;
- `Restore-PwDeployment`.

No catalog, cache, profile, archive, package, deployment, game, restore, Git ref,
or tracked-file mutation is part of dashboard collection.
